# Data-Points Spec (Phase 0 draft + Phase 2 grounding)

Date: 2026-08-04, updated after the second local probe run (nflreadpy now working). Status: **grounded — every row below has hands-on evidence** except the two rows gated on your FantasyPros/API-Sports keys.

| Category | Data point | Status | Evidence / notes |
|---|---|---|---|
| Player identity & rostering | Position, team, active/inactive | **Confirmed available** | Hands-on confirmed: nflreadpy `load_rosters()` (3,137 rows, real `status` breakdown: ACT/DEV/CUT/RES/INA/RET/TRD/TRC) and Sleeper's 12,207-player dump both carry this, plus nflreadpy's roster rows already include most cross-source IDs directly |
| Player identity & rostering | Bye week | Confirmed available (not separately hands-on probed) | Standard field in nflreadpy schedules per docs; low risk, not worth a dedicated probe call |
| Player identity & rostering | Cross-source player ID | **Confirmed available, with a gap** | Hands-on confirmed today via `db_playerids.csv` — real crosswalk exists and covers a 2026 rookie (Fernando Mendoza) for most ID columns, **but `fantasypros_id` is NA for that rookie**. Engine needs a fallback join key (e.g. `sleeper_id`) for newly-drafted players, not a straight `fantasypros_id` join. nflreadpy's own rosters table also carries most of these IDs directly, reducing how much you actually need this crosswalk for in-season players |
| Recent performance | Last-N-games stats, season-to-date stats | **Confirmed available** | Hands-on confirmed: nflreadpy `load_player_stats()`, 19,421 rows, 2025 weeks 1–22, ~140 columns including full passing/rushing/receiving lines. **Bonus: includes `fantasy_points`/`fantasy_points_ppr` directly** — real historical fantasy output, useful for the eval/backtest layer too, not just the value engine |
| Recent performance | Usage trend (snap %, target share) | **Confirmed available** | Same pull: `target_share`, `air_yards_share`, `wopr`, `racr` are real columns in the 19,421-row dataset |
| Matchup context | Opponent | Confirmed available (trivial) | Schedule data, low risk, not separately probed |
| Matchup context | Opponent defensive strength vs. position | **Computed in-house** | Known gap per the plan — no source has this as a direct field; confirmed no contradicting evidence found in today's probing either. Needs to be derived from raw team defensive stats (nflreadpy team stats, once accessible) |
| Forward-looking projection | Weekly fantasy points by scoring format | **Confirmed available for top-10-per-position players only — hard ceiling, no override** | Hands-on confirmed: FantasyPros' `projections` endpoint returns real per-player `points`/`points_ppr`/`points_half` plus underlying stat-line projections. But 6 different attempts to get past the free tier's 10-player-per-position cap (`player_id`, `id`, `fpid`, `limit=50`, `offset`, `page`) all returned the identical top-10 list — **confirmed no workaround exists on this tier**. The `scoring` parameter is also confirmed to have no effect (ignored; all formats returned regardless) — not a problem, since every response already includes `points`/`points_ppr`/`points_half` together. **Net effect: no source in this candidate list has projections for bench/waiver-tier players** — see `scope-note-draft.md` for the recommended mitigation (in-house estimate from nflreadpy for everyone outside FantasyPros' top 10) |
| Consensus rankings (ECR) | Sanity-check baseline | **Confirmed available** | Hands-on confirmed: `db_fpecr.csv.gz`, real columns `ecr/sd/best/worst/rank_delta/ecr_type`, 1.5M rows spanning the full historical archive — filter by `scrape_date`/season before use |
| Injury/practice status | Designation (Q/D/O) | **Confirmed available, dual-sourced** | Hands-on confirmed both sides: Sleeper's dump has `injury_status`/`injury_body_part`/`injury_start_date`/`injury_notes`; nflreadpy's `load_injuries()` (6,068 rows) has `report_status`/`report_primary_injury`/`report_secondary_injury`. Genuine redundancy for Phase 5 cross-checking once both sources have same-week in-season data |
| Injury/practice status | Practice participation trend | **Confirmed available, dual-sourced** | Hands-on confirmed both sides: Sleeper has `practice_participation`/`practice_description`; nflreadpy's injuries table has `practice_status`/`practice_primary_injury`/`practice_secondary_injury` (`has_practice_participation_field: true`, checked directly). This was the specific unknown Phase 1 flagged, and it's now answered by both sources |
| Game context | Home/away, Vegas implied total, weather | **Out of scope for v1** | Confirmed no source in this candidate list carries this — matches the plan's original flag; a v2 item requiring an odds API, a genuinely different sourcing category |
